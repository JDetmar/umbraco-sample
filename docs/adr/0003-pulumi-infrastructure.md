# 0003. Pulumi (C#) with Pulumi Cloud state for all Azure infrastructure

- Status: Accepted
- Date: 2026-11-24
- Decider: owner
- Clauses: ES-019, ES-013, ES-024, ES-055, ENV-01

## Context

All Azure resources must be defined as code with no manual changes (ENV-01). Material state-changing operations need a preview before execution (ES-055), and credentials must stay out of source and CI definitions (ES-024).

## Alternatives considered

- **Bicep:** native to Azure and free, but a separate language from the application and weaker abstraction for three similar environments.
- **Terraform:** widely known, but HCL is a separate language and state hosting must be arranged.
- **Bicep generated by Aspire:** convenient, but couples infrastructure to the local orchestration tool's release cadence.

## Decision

Pulumi in C# (`infra/`) with the Azure Native provider, one stack per environment (dev, staging, prod). State and encrypted config secrets live in Pulumi Cloud, which the owner already uses. `pulumi preview` runs on every pull request; `pulumi up` runs only from the pipeline after merge and only with owner approval for each environment. GitHub authenticates to Azure with OIDC federation, so no cloud secret is stored.

## Consequences

- Infrastructure code shares the language, analyzers and review rules of the application.
- Pulumi Cloud becomes a service dependency; exit is `pulumi stack export` to a self-managed backend.
- Provider versions are pinned through the lock file like any other package.
